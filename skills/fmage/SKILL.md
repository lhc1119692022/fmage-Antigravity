# Fmage

- Reply in Chinese unless asked otherwise; this applies only to user-facing prose, not tool argument content. Keep provider names, model IDs, JSON keys, URLs, env vars, and paths unchanged.
- Use Fmage MCP tools, not scripts. Choose `generate_image` or `edit_image` for one request and the matching batch tool for multiple independent requests. Provider routing is automatic after provider selection; call the selected base tool directly without enumerating or rediscovering tools.
- Fast path for normal image work: perform exactly one concise understanding-and-expansion pass in the current turn, preserve every explicit user constraint, add only missing details needed by the image model, and call the matching base tool immediately. If the request is already complete, keep the prompt nearly unchanged. Output only the final prompt; do not write analysis, a plan, multiple candidates, a separate prompt-optimizer call, or a status/trace preflight.
- Keep normal Fmage work in the current task. Do not create subagents for prompt writing, translation, comparison, attachment inspection, image submission, or waiting. Put multiple independent image jobs into one Fmage batch call.
- Treat every failed or partial image call as terminal for the current attempt. Stop and report its error or warning. Do not retry the same provider, change parameters and retry, select another provider, or call status/discovery tools to find an alternative provider unless the user explicitly asks for or approves another image call. Do not add a prompt optimizer, prompt-cache lookup, status/trace preflight, or second prompt-rewrite pass.
- When a user attachment is already clearly visible and its role is unambiguous, pass its supplied path directly to `edit_image`; do not separately open, render, or inspect it first. Inspect only when the requested change depends on details not visible in the attachment preview or when the image role/content is ambiguous.
- After a successful image result, do not call `view_image` or another inspection tool unless the user explicitly requested visual QA or the requested result cannot be verified from the returned metadata.
- Waiting and provider polling are necessary. Let the image tool perform its internal wait. For an asynchronous return, keep exactly one waiter or status check active, use the longest practical wait window, and poll again only after that wait reports the task is still incomplete; never issue concurrent or duplicate status checks.
- Put the result of that one pass in `prompt`, with one complete prompt per batch job. Apply only the constraints relevant to the request; do not perform a separate intent-classification step or expose analysis.
- For every input image, identify it by index and role in the prompt, such as `Image 1: edit target`, `Image 2: style reference`, `composition reference`, `subject reference`, `base scene`, `supporting insert`, or `character anchor`. Do not assume every input is an edit target. When an image is guidance only, state what may be borrowed and what subject, composition, background, or content must not be copied.
- For edits, explicitly state `change only X; keep Y unchanged` and repeat the critical invariants on every iteration. Lock all applicable identity, pose, geometry, proportions, framing, camera angle, untouched regions, edges, layout, typography, text, palette, and style. For compositing, name what moves from which image into which base image and require matched lighting, perspective, scale, shadows, and color temperature.
- Map an explicit user request for a transparent background, no background, or a cutout to `background: "transparent"`; do not infer transparency from ordinary requests for a white, solid, clean, or minimal background. Keep `output_format: "png"` by default. If the user explicitly requests JPEG together with transparency, pass that explicit format so the image tool rejects the incompatible request before any provider call; do not silently coerce it.
- Quote required in-image text verbatim, require no extra characters, and preserve typography, spacing, placement, and hierarchy when the task changes only text. For complex requests, use only the helpful labels from: `Use case`, `Primary request`, `Input images`, `Scene/backdrop`, `Subject`, `Style/medium`, `Composition/framing`, `Lighting/mood`, `Text (verbatim)`, `Change`, `Keep unchanged`, `Match`, and `Avoid`; omit unused labels.
- Separate delivery parameters from visual language. `quality` controls generation quality/cost/speed; it does not mean sketch, wireframe, placeholder, grayscale, or any other visual style. Keep the requested finished-art direction in the prompt even when `quality` is `low`.
- Treat `output_format` like other delivery overrides: omit it for ordinary image requests so PNG remains the default; pass `output_format_user_requested: true` only when the user explicitly asks for JPEG, WebP, or another non-default format.
- Omit `quality` only when the user did not select a quality/speed/cost tier, so the plugin uses the model default `high` for image-series models. When the user explicitly selects any tier, including `medium`, always pass that exact `quality`. If the selected tier differs from the model default, also pass `quality_user_requested: true`. Never infer a tier from resolution alone or infer `high` from professional, final, retouch, color correction, or editing language.
- Explicit `草图质量`, draft quality, preview quality, or low quality selects `quality: low` and `quality_user_requested: true`; for draft/草图 quality also use `resolution: 1k` and `resolution_user_requested: true` unless another resolution was requested. A resolution request alone never selects quality.
- Treat sketch, hand-drawn, wireframe, and low-fidelity as visual styles only when explicitly requested. Resolve ambiguous `草图` from context without injecting wireframes, gray placeholders, or sketch styling; ask only when the distinction materially changes the result.
- Treat `占位素材`, `临时封面`, and `示意内容` as complete fictional but plausible content in the requested finished style, not empty boxes. Treat `效果图` as a coherent finished composition without decorative annotations or invented copy unless requested.
- Pass optional params only when specified or necessary; omit `provider` unless named and `output_dir` unless a save folder is specified. Never choose `resolution` or exact `size` merely from composition, aspect ratio, intended use, model capability, or visual-quality wording. Phrases such as `具备8K超高分辨率`, `8K画质`, `超高清`, `极致清晰`, or `ultra-high-resolution` describe the desired image effect and stay in `prompt`; they do not set a delivery parameter. When the user explicitly selects a delivery resolution tier or exact size, always pass it and set `resolution_user_requested: true`; otherwise omit both so the model default applies. Named providers must be active and may be selected by their full name or a unique `active_providers` shorthand.
- Never derive image-model `thinking_level` from the host session reasoning level. Omit it unless the user explicitly requests it; when requested, pass the value with `thinking_level_user_requested: true`. The server validates it against the resolved provider/model, including after provider shorthand is expanded.
- Treat `1k`, `2k`, `3k`, and `4k` as resolution tiers, not fixed edge lengths. The selected transport resolves the tier and aspect ratio to the actual request dimensions; `requested_size` is authoritative. When saved image dimensions equal `requested_size` and there is no size warning, report normal success. Never compare a tier result with `4096x4096`, call it undersized/nonstandard/provider-capped, or offer a stricter retry unless the user explicitly requested an exact `WIDTHxHEIGHT`.
- Image-series models default to `quality: high`. `gpt-image-2` series models, including `gpt-image-2.5-flare` and `gpt-image-2.5-sunburst`, also default to the `4k` resolution tier. Preserve any explicit user-selected size, resolution, or quality tier.
- Completed output is compact and path-based. Use `display_images` for inline Markdown, for example `![Generated image](C:/Users/name/.gemini/antigravity/fmage/outputs/provider/run/image_1.png)`. No backslashes or `file://`.
- Final responses for completed images: prompt summary, provider/model, saved path(s), dimensions, manifest path, and inline images. Do not add a warning line when there is no blocking error. Mention a size mismatch only when the actual dimensions differ from `requested_size` or the plugin returns a size warning.
- For provider/config questions, setup, dry runs, trace/verbose output, failed/partial requests, or unusual async diagnosis, read [diagnostics.md](references/diagnostics.md) before acting. Normal generation, editing, and ordinary async waiting use the rules above without loading another reference.
